# Доклиб: ссылка на папку открывает предыдущую папку (COREDEV-355)

## Проблема

Аналитик: в библиотеке документов выделяешь папку, копируешь ссылку из адресной строки, потом
переходишь по ней — открывается не папка из ссылки, а «какая-то последняя открытая». Поведение
выглядело плавающим: у одного воспроизводится, у другого нет.

### Воспроизведение (локальный стенд, `news-journal`)

Локально доклиб включён у типов `news`, `project-milestone`, `corpport-*`; папок на стенде нет,
их надо создать (через UI или `records/mutate` с `_parent: emodel/doclib@news$`,
`_type: emodel/type@doclib-directory`). Режим вида в URL называется **`viewMode=document-library`**
(`JOURNAL_VIEW_MODE.DOC_LIB`) — `viewMode=doclib` это неизвестный режим, журнал молча падает в таблицу.

1. Открыть `/v2/journals?journalId=news-journal&viewMode=document-library&ws=admin$workspace`.
2. Открыть папку A, затем папку B (в дереве или даблкликом). URL содержит `folderId=B`.
3. Перейти по ссылке на папку A **внутри приложения** — кликом по ссылке в комментарии, на дашборде,
   из другой вкладки приложения (ECOS-вкладка, не браузерная).

ФР: URL показывает `folderId=A`, дерево и список файлов показывают B. ОР: открыта папка A.

Замеры до исправления:

| Как перешли по ссылке | Результат |
|---|---|
| вставить в адресную строку / новая вкладка браузера (полная загрузка) | верно |
| клик по ссылке внутри приложения, доклиб на экране | **старая папка** |
| клик по ссылке внутри приложения с другой ECOS-вкладки (дашборд) | **старая папка** |
| кнопка «Назад» браузера | не путь: смена папки делает `replace`, записи истории нет |

Поэтому и «плавает»: всё зависит от того, была ли уже открыта вкладка этого журнала. Ничего в
localStorage «не запоминается» — там только раскрытые узлы дерева (`LS_UNFOLDED_PREFIX`).

## Корневая причина

Три факта складываются в баг:

1. **Вкладки приложения ключуются журналом.** `PageService.getKey` для `PageTypes.JOURNALS` —
   это `journalId`, `folderId` в ключ не входит. Ссылка на другую папку того же журнала не создаёт
   новую вкладку: `PageTabList.setTab` находит существующую и просто обновляет ей `link`.
2. **Страница вкладки закэширована** (`CacheRoute` в `App.jsx`), `Journals`/`DocLibView` остаются
   смонтированными. `Journals.componentDidUpdate` честно обновляет `journals[stateId].url`
   (проверено дампом стора: `url.folderId = A`, `documentLibrary.folderId = B`).
3. **Доклиб читает `folderId` из URL один раз** — в `sagaInitDocumentLibrary` через `selectUrl`,
   а `DocLibView` диспатчит `initDocLib` один раз на `typeRef` (`initializedTypeRef`). На смену
   `url.folderId` никто не подписан.

Попутно найдено (не чинилось, вне задачи): в `helpers/urls.js` `equalsQueryUrls` условие
`if (!ignored || !ignored.length) { omit(...) }` перевёрнуто — список `ignored` никогда не
применяется. Для этого бага это оказалось «полезно» (иначе `Journals` не обновлял бы `url` при
смене только `folderId`), но все вызовы с `ignored` (`Journals.jsx`, `PageTabList.equalsLink`)
сравнивают полный query.

Ещё одна особенность, важная для исправления: при уходе на другую ECOS-вкладку
`journals[stateId].url` доклиба транзиентно затирается параметрами той страницы (например
`{ ws }` дашборда, без `viewMode`), а при возврате восстанавливается из `tab.link`.

## Исправление

`src/components/journals/Journals/DocLib/hooks/useFolderFromUrl.ts`, подключён в `DocLibView`
после эффекта инициализации, с `enabled = isInitialized && isActivePage`.

- Источник истины — сторовый `journals.url` (его читает и init-сага, его ведёт `Journals` для
  активной страницы, для фоновых вкладок он не меняется), а не `window.location`.
- Целевая папка: `url.folderId || rootId`, и только если `isDocLib(url.viewMode)` — иначе
  транзиентные параметры дашборда или ссылка на табличный вид того же журнала сбрасывали бы папку.
- Текущая `folderId` читается через ref: эффект срабатывает **только на смену URL**. При клике
  пользователя сначала меняется `folderId` в сторе, URL догоняет позже — к тому моменту они равны,
  пинг-понга нет.
- Расхождение → `openFolder(target)`: та же сага, что и клик по папке (сброс выделения, пагинации,
  поиска, раскрытие узла дерева). Она повторно пушит тот же URL через `changeUrlLink(updateUrl)` —
  безвредно.

Тесты: `DocLib/__tests__/useFolderFromUrl.test.js` (реальный redux-стор с middleware-рекордером:
переход по ссылке, корень, отсутствие пинг-понга, игнор чужих видов, до инициализации, `enabled`).

Проверено в браузере после исправления: оба сломанных сценария открывают папку из ссылки, ссылка
на корень возвращает в корень; регрессии нет — клик/даблклик по папкам, возврат на вкладку через
полоску вкладок сохраняет открытую папку, полная перезагрузка по ссылке работает как раньше.
