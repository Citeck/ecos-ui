# Lexical: меню ячейки таблицы и меню тулбара (COREDEV-455)

## Проблема

В контекстном меню ячейки таблицы (шеврон в ячейке → `TableActionMenu`) часть пунктов стояла по
центру, часть — по левому краю. Тестировщик перечислил «Объединить ячейки», «Цвет фона»,
«Переключить чередование строк», «Вертикальное выравнивание», «Закрепить/открепить первую
строку/столбец».

Замер на локальном стенде (русский интерфейс, отступ строк подписи от левого края `.text`):

| пункт | до | после |
|---|---|---|
| «Переключить чередование строк» (2 строки) | 16 / 97 px | 0 / 0 |
| «Закрепить/открепить первую строку» (2 строки) | 8 / 93 px | 0 / 0 |
| «Закрепить/открепить первый столбец» (2 строки) | 7 / 88 px | 0 / 0 |
| однострочные («Цвет фона», «Удалить строку», …) | 0 | 0 |

То есть по центру стояли ровно те подписи, которые **переносятся на вторую строку** — самые длинные
русские; однострочные всегда были слева. На английском интерфейсе ни одна подпись не переносится,
и бага не видно.

## Корневая причина

Пункт меню — `<button class="item">` (`plugins/TableActionMenuPlugin/TableActionMenu.tsx`). У кнопки
браузерный default `text-align: center`, а в `Lexical/index.scss` блок
`.citeck-lexical-editor__dropdown .dropdown .item` его не сбрасывал. Подпись `.item .text` —
`display: flex; flex-grow: 1; min-width: 180px`: однострочный текст в ней — анонимный flex-элемент
шириной по содержимому, прижат к началу и центрирования не показывает; текст с переносом занимает
всю ширину `.text`, и строки внутри него центрируются унаследованным `text-align`. Локальная
заплатка от того же бага уже была у подменю вертикального выравнивания
(`.item.wide .icon-text-container .text { text-align: left }`).

## Исправление

`src/components/editors/Lexical/index.scss`: `text-align: left` у `.dropdown .item` и у дубля
`&__dropdown .item`. Меню тулбара (`item.wide` с шорткатом справа) не затронуто — там подпись и
шорткат расставлены flex'ом.

## Проверка

Браузер (локальный стенд, `/v2/dashboard?ws=TEST&recordRef=emodel/ept-issue@TEST-1`, комментарий →
«Вставка» → «Таблица» → шеврон ячейки; язык «Рус» через меню пользователя): у всех 14 пунктов
`text-align: left`, все строки подписей с отступом 0 (`Range.getClientRects()` относительно
`.text`); меню тулбара «Обычный/Заголовок…» — подпись слева, шорткат справа, как и было.

## Второй заход (2026-09-02): меню тулбара вылезало за контейнер

Тестировщик 2026-08-31 вернул задачу: меню ячейки таблицы в порядке, но в меню стиля тулбара
(«Обычный / Заголовок 1 / …») строки «Цитата» (Ctrl+Alt+Q) и «Блок кода» (Ctrl+Alt+C) вылезают
за правую границу выпадающего списка.

### Что на самом деле

Вылезали **все** строки **всех четырёх** меню тулбара, а не две — на подсвеченной строке это просто
заметнее. Замер на локальном стенде (правый край пунктов минус правый край контейнера):

| меню | ширина контейнера | перелёт |
|---|---|---|
| стиль («Обычный…»), `.item.wide` 248px | 200px | 56px |
| формат текста, `.item.wide` | 200px | 56px |
| «Вставка», `.item` с `.text` min-width 180px | 200px | 36px |
| выравнивание, `.item.wide` | 200px | 56px |

Меню ячейки таблицы не задето: `TableActionMenu` рендерится порталом в свой `div.dropdown` без
классов общего дропдауна.

### Корневая причина

Меню тулбара строит `DropdownPreview` (`components/common/form/Dropdown/DropdownPreview.tsx`), который
наследует от базового `Dropdown` классы `ecos-dropdown__menu ecos-dropdown__menu_new`. В
`Dropdown.scss` у `_new` и его `ul` стоит `max-width: $max-width-dropdown-menu !important` = 200px —
кап под однострочные текстовые `li` с многоточием. Пункты Lexical — кнопки фиксированной ширины
(`.item.wide` 248px с COREDEV-95, 2026-06-22), они не сжимаются, и контейнер оказывается уже
содержимого. Это не регрессия первого исправления: `text-align` ширины не меняет; так было с
COREDEV-95, а заметили при проверке по подсказке «меню тулбара — подпись слева, шорткат справа».

### Исправление

`src/components/editors/Lexical/index.scss`, блок `&__dropdown`: `max-width: none !important` для
`.ecos-dropdown__menu_new` и его `ul` — меню тулбара подстраивается под свои пункты (`!important`
нужен, потому что капающее правило само с `!important`; у нашего селектора специфичность выше).

Заодно `src/testUtils/cssCascade.js` теперь подмешивает `@use "@/styles/breakpoints" as *` так же, как
Vite (`additionalData`), иначе любой scss с `media-down(...)` (в том числе `Dropdown.scss`) не
компилируется в тесте.

### Проверка

- Тест `src/components/editors/Lexical/__tests__/dropdownMenuWidth.test.js` (каскад через sass CLI):
  голый `_new` капается 200px; внутри `.citeck-lexical-editor__dropdown` у меню и `ul` — `none`;
  `.item.wide` по-прежнему 248px.
- Браузер, локальный стенд, комментарий к `TEST-1`: все четыре меню тулбара — правый край пунктов
  на 8px левее края контейнера (это `margin` пункта); ширины 264 / 264 / 244 / 264px. Меню языка
  кода (17 `li`) — 212px, ничего не расползлось. Русский интерфейс: все шорткаты внутри контейнера,
  «Маркированный/Нумерованный список» переносятся на две строки, подпись слева. Меню ячейки таблицы
  (проверено на английском): 220px, все 14 пунктов `text-align: left`, строки подписей с отступом 0,
  пункты внутри контейнера.
