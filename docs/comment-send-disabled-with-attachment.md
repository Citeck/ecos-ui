# Комментарий из одного вложения не отправляется: кнопка «Отправить» заблокирована

## Проблема

В виджете комментариев прикрепляем файл (кнопка загрузки на панели редактора) — кнопка «Отправить»
остаётся серой, будто контента нет. Стоит набрать любой символ — кнопка разблокируется; удалить
символ — снова блокируется, хотя вложение никуда не делось.

Рядом обнаружились две сестринские аномалии того же места:

- комментарий из одной вставленной картинки тоже не отправлялся;
- зато два пустых абзаца (просто нажать Enter) отправить было можно.

## Корневая причина: пустота определялась подстрокой в DOM редактора

Единственное место, где решается «в редакторе пусто», — `Editor.tsx`, третий аргумент `onChange`
(его потребляет только `Comments/Comment.jsx`, состояние `isEditorEmpty` → `disabled` у кнопки):

```jsx
const { innerHTML = '' } = editor.getRootElement() || {};
onChange(state, editor, textContentSize === 0 && !innerHTML.includes('img') && !innerHTML.includes('hr'));
```

- `getTextContentSize()` у любого `DecoratorNode` — ноль: `FileNode`, `ImageNode`, разделитель,
  формула, опрос своего текста не имеют.
- Дальше — поиск подстрок `img` и `hr` **в живом DOM contenteditable**. У вложения DOM такой:
  `<span data-lexical-decorator><span class="file-node__link">имя.txt</span></span>` — ни `img`, ни
  `hr`, поэтому «пусто». Картинка проходила только потому, что React успевал отрисовать реальный
  тег `<img>`, а это гонка: декоратор рисуется на коммит позже, чем срабатывает `OnChangePlugin`,
  плюс `LazyImage` держит Suspense, пока изображение не загрузится. Отсюда «иногда работает».
  Разделитель `hr` проходил случайно — и по той же причине любой `href=` в разметке считался бы
  контентом.
- Пустые абзацы: `RootNode.getTextContent()` склеивает блоки двойным переносом, так что у двух
  пустых абзацев «текст» длиной 2 — не ноль, кнопка разблокируется.

## Исправление

`src/helpers/lexical.ts` — общий `$isEditorContentEmpty()` рядом с `updateEditorContent`, который уже
пользуется той же идиомой `$isDecoratorNode`:

```ts
export function $isEditorContentEmpty(): boolean {
  const root = $getRoot();

  return root.getTextContent().trim() === '' && !hasDecorator(root);
}
```

`hasDecorator` спускается по дереву, так что картинка в ячейке таблицы тоже считается контентом.
`Editor.tsx` берёт флаг из состояния документа в том же `state.read`, что и длину текста; чтение
`innerHTML` убрано — гонки с отрисовкой React больше нет.

Пустой таблицей поведение не менялось: таблица без текста по-прежнему читается как пустой
комментарий.

## Проверка

- `src/helpers/__tests__/lexicalContentEmpty.test.ts` — пусто: ничего, пустой абзац, два пустых
  абзаца, одни пробелы; контент: текст, вложенный файл, картинка, разделитель, картинка и текст в
  ячейке таблицы.
- Браузер (локальный стенд, виджет комментариев `emodel/ept-issue@TEST-1`): до правки вложение
  оставляло «Отправить» серой, символ разблокировал, удаление символа снова блокировало. После
  правки: пусто — серая; три пустых абзаца — серая; одни пробелы — серая; текст — активна;
  **одно вложение — активна**, комментарий отправляется и показывается со ссылкой на файл.
  Картинка: активна сразу после вставки (ещё до конца загрузки), после Ctrl+Z — снова серая.
