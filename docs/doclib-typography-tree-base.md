# Доклиб: разный размер шрифта в дереве папок и в основной области (COREDEV-355, п. 4)

## Проблема

Пункт задачи: «Разный размер шрифта в дереве папок, основной таблице и хедере». Решение по ходу
задачи: хедер может отличаться (это заголовок страницы), **выравниваем дерево и основную область,
за базу берём размер дерева**.

### Замеры до исправления (computed, локальный стенд)

| Элемент | размер / вес |
|---|---|
| строка дерева `.citeck-doclib-tree__row` | 13.33px (`$font-size-standard`) / 600 |
| имя файла в списке `.citeck-doclib-files__row-title` | **11px** / 600 |
| дата в списке `.citeck-doclib-files__row-modified` | **11px** / 600 |
| шапка списка `.citeck-doclib-files__head` | 11px / 700 |
| заголовок карточки в сетке | 13.33px / 600 |
| крошки, тулбар, поиск | 13.33px / 600 |

Одна и та же папка читалась 13px в дереве и 11px в списке рядом. В 2026.2 (скриншот в задаче)
дерево и список были одного размера.

## Корневая причина

`Files/FilesArea.scss`: строка списка и колонка даты скопировали типографику журнальной таблицы
(`.ecos-grid__td`, 11px/600 — так и написано в комментарии), тогда как дерево, карточки сетки,
крошки и тулбар живут на `$font-size-standard`. Список оказался единственным «мелким» местом.

## Исправление

`FilesArea.scss`: `&__row` и `&__row-modified` → `$font-size-standard` / `$font-weight-semi-bold`,
как `.citeck-doclib-tree__row`. Высота строки (44px) и обрезка длинных имён не изменились.

Шапка списка (`Name` / `Modified`) в этот заход была оставлена 11px bold как «подпись колонок в
стиле заголовка журнальной таблицы». Это оказалось неверно: `.ecos-th` в `HeaderFormatter.scss`
живёт на `$font-size-standard` (13.33px), 11px там нет. По повторной проверке (COREDEV-355, п. 11,
см. `doclib-review-remarks.md`) шапка списка тоже переведена на `$font-size-standard` / 700 — теперь
вся библиотека, включая подписи колонок, читается одним размером. Хедер страницы не трогал
(решение выше).

Тест: `DocLib/__tests__/filesTypography.test.js` — компилирует `FolderTreePanel.scss` и
`FilesArea.scss` и по каскаду проверяет, что `font-size`/`font-weight` имени и даты в строке списка
равны строке дерева. Без правки падает (`11px` vs `10pt`).

Проверено в браузере: дерево 13.33/600, имя и дата в списке 13.33/600, карточки сетки 13.33/600;
строки 44px, переполнения имён нет. (Шапка списка на тот момент ещё была 11px/700 — см. выше.)
