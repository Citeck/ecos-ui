# Tooltip: подсказка кнопки импорта и «полупрозрачные» подсказки (COREDEV-408)

В задаче два независимых дефекта: подсказка кнопки импорта не появлялась совсем, а остальные
подсказки появлялись не сразу и полупрозрачными. Ниже — каждый по отдельности.

## Проблема 1: у кнопки импорта нет подсказки

В панели инструментов журнала кнопкам «Экспорт» и «Импорт» добавили подсказки
(`JournalsSettingsBar.jsx`, коммит `5ec4155`). После проверки задача вернулась: у экспорта
подсказка появляется, у импорта — нет. Разметка и код обеих кнопок при этом симметричны:
обе обёрнуты в `<Tooltip target={...}>`, обе получают `id` на корневой элемент.

### Воспроизведение

1. Открыть журнал, у типа которого есть варианты импорта (иначе кнопка не рендерится вовсе).
2. Навести курсор на кнопку «Импорт».

ФР: подсказки нет и не будет до перезагрузки страницы. ОР: подсказка «Импорт», как у экспорта.

## Корневая причина

`TooltipWrapper` вешает обработчики `mouseover`/`mouseout` на элемент, который `getTarget`
(reactstrap) находит по `id` **в момент монтирования** — `updateTarget()` вызывается только из
`componentDidMount` и из `render()`, а `render()` до этого выходит по `if (!this.props.isOpen ||
this.props.isHiddenTarget) return null`. То есть пока подсказка закрыта, цель повторно не ищется.

Разница между кнопками — в моменте появления цели в DOM:

- `Export` рендерит свой корневой `div` (с `id`) синхронно;
- `Import` в `componentDidMount` запрашивает варианты импорта
  (`integrations/import-data-variant`) и до ответа возвращает `null` (`Import.jsx`, проверка
  `if (!allowVariants.length || hideImportDataActions) return null`).

Когда `TooltipWrapper` монтируется, элемента `#…-import` в документе ещё нет: `getTarget` бросает
исключение, `_targets` остаётся пустым, обработчики не вешаются. Кнопка появляется через сотни
миллисекунд, но повторно цель никто не ищет — ховер остаётся «немым» на всё время жизни страницы.

Это общий дефект, а не особенность импорта: любая подсказка, чья цель монтируется позже неё,
не работала.

## Исправление

`src/components/common/Tooltip/TooltipWrapper.jsx`:

- подсказки, для которых цель не найдена, складываются в общий `Set` и отслеживаются **одним**
  `MutationObserver` на `document.body` (`childList`, `subtree`); при добавлении узлов каждая
  ждущая подсказка заново вызывает `updateTarget()` и, найдя цель, вешает обработчики и выходит из
  наблюдения. Наблюдатель создаётся только когда кто-то ждёт цель, и отключается, когда ждущих не
  осталось (в том числе при `componentWillUnmount`);
- `updateTarget()` сравнивает **массив элементов**, а не `NodeList` с массивом: прежнее сравнение
  никогда не было равным, из-за чего обработчики переустанавливались при каждом вызове (с
  наблюдателем это происходило бы на каждую пачку мутаций).

Показ подсказки после этого доезжает сам: первый `mouseover` меняет `Tooltip.state.isOpen`, а
`componentDidUpdate` → `stealthCheck()` пересчитывает `isHiddenTarget` уже по существующей цели.

## Проверка

- `src/components/common/Tooltip/__tests__/Tooltip.test.js` — сценарий с целью, которая
  монтируется после подсказки; до исправления падает.
- `src/components/domain/Import/__tests__/Import.test.js` — тот же сценарий на настоящем `Import`
  внутри `Tooltip`: ховер по кнопке, появившейся после ответа сервера, показывает подсказку; до
  исправления падает.
- Полный прогон `jest`: 221 сьют / 2844 теста — зелёные.
- Браузерная проверка на локальном дев-сервере (журнал `ecos-journals`): до исправления ховер по
  импорту не даёт подсказки, а по экспорту даёт; после — «Импорт» появляется и по иконке, и по
  стрелке дропдауна, подсказки соседних кнопок («Обновить данные», «Настройки таблицы», «Экспорт»)
  не сломаны.

### Как увидеть кнопку импорта локально

На локальном стенде приложение `integrations` не поднято, поэтому запрос вариантов импорта падает
и кнопка не рендерится никогда. Чтобы получить её в браузерном тесте, ответ подменяется на уровне
сети (Playwright `context.route`): перехватывать надо `**/gateway/**` — URL запроса
`/gateway/api/records/query?k=q_integrations_import_data_variant`, и глоб без учёта query-строки по
нему не срабатывает. Тело ответа: `{"records":[{"variantId":"csv","name":"CSV","allowedFor":[]}]}`.

## Проблема 2: подсказки появляются не сразу и полупрозрачными

Из комментария к задаче: подсказки в шапке «появляются сразу не полностью, как будто выплывают
из-под элементов».

### Корневая причина

Никакого перекрытия слоями нет (ложный след: `document.elementFromPoint` в центре подсказки
возвращает `div.page-tab`, но лишь потому, что у hover-подсказок `pointer-events: none`, — они
прозрачны для попадания курсора, а не спрятаны под лентой вкладок). Дело в анимации появления.

`Fade` (reactstrap) навешивает свой класс `show` только в статусе `entered`:

```js
var isActive = status === 'entered';
classes = classNames(className, baseClass, isActive && baseClassActive);
```

`entered` наступает **через `timeout`** (у reactstrap — 150 мс), и только тогда стартует CSS-переход
`.fade { transition: opacity .15s }`. То есть JS-таймаут и CSS-анимация шли **последовательно**.

Замер по кадрам на локальном стенде (наведение на кнопку «Обновить данные»):

| момент | было | стало |
| --- | --- | --- |
| подсказка в DOM, но полностью прозрачна | 0–155 мс | 0–19 мс |
| первый видимый кадр | ~158 мс | ~19 мс |
| полностью непрозрачна | ~311 мс | ~164 мс |

Первые ~150 мс на экране висел невидимый блок, следующие ~150 мс — полупрозрачный, сквозь который
просвечивала панель. Это и выглядит как «выплывает из-под элементов»; на скриншоте, снятом через
250 мс после наведения, подсказка бледная и сквозь неё видно тулбар.

Отдельно: в самом первом кадре (t≈1 мс) поппер стоит в точке (0, 0) — Popper позиционирует его на
следующем кадре. Прозрачность в этот момент нулевая в обоих вариантах, так что артефакт не виден.

### Исправление

`src/components/common/Tooltip/TooltipContent.jsx`: таймаут перехода для `Fade` — `0`, анимацией
владеет CSS. Класс `show` попадает на элемент на следующем тике после монтирования, и переход
`opacity` идёт сразу, укладываясь в свои 150 мс.

Путь закрытия не затронут: `TooltipWrapper.render()` при `isOpen === false` сразу возвращает `null`,
контент размонтируется, exit-перехода тут нет и не было.

### Проверка

- `src/components/common/Tooltip/__tests__/Tooltip.test.js` — сценарий «становится видимой, не
  дожидаясь таймаута»: через 40 мс после наведения на обёртке должен быть класс `show`; без
  исправления падает.
- Браузер, те же фиксированные задержки после наведения: было `opacity` 0 на 80 мс и 0.6 на 250 мс,
  стало 0.46 на 80 мс и 1 на 250 мс.

## Замечание по инструментам

`page.screenshot({ clip })` в Playwright не показывает эти подсказки: они вынесены порталом в конец
`body`, и при съёмке по clip попадают мимо кадра — по такому скриншоту легко решить, что подсказки
нет вовсе. Снимать надо полный вьюпорт, а `getBoundingClientRect`/`getComputedStyle` использовать
как источник истины.
