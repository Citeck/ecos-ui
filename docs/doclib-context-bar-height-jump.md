# Доклиб: граница области файлов «скачет» (COREDEV-355)

## Проблема

Верхняя граница области файлов (низ панели с хлебными крошками и пагинацией) стоит на разной
высоте в разных папках и прыгает вверх-вниз при перекликивании папок в дереве. По наблюдению —
«зависит от числа крошек: пусто / одна / больше одной».

### Замеры до исправления (локальный стенд, `news-journal`)

| Состояние | крошек | пагинация | высота панели | top области файлов |
|---|---|---|---|---|
| корень, есть содержимое | 0 | есть | **40** | 218 |
| Folder A, есть содержимое | 1 | есть | **40** | 218 |
| Sub C, пустая папка | 2 | нет (`total = 0`) | **34** | 212 |
| клик по папке, ответ ещё не пришёл | — | нет | **34 → 40** | 212 → 218 |

Число крошек ни при чём (крошки 28px и всегда помещаются) — совпадение с тем, какие папки пустые.
Переменная одна: отрисована ли `Pagination`.

## Корневая причина

- `.citeck-doclib__context-bar` — `min-height: 34px`, высоту задаёт содержимое.
- `Pagination` рендерит стрелки `IcoBtn` с классом `ecos-pagination__arrow_new`. Правило
  `Pagination.scss` `.ecos-pagination__arrow.ecos-btn { height: 20px }` написано для класса
  `ecos-pagination__arrow`, которого у стрелок нет, — работает базовое `button.ecos-btn { height: 40px }`
  (`Btn.scss`). Стрелки 40px растягивают панель до 40.
- `Pagination.render` возвращает `null` при `!total`, а `sagaOpenFolder` сбрасывает
  `setFileViewerTotal(0)` перед загрузкой — пагинация размонтируется на время каждой загрузки и в
  пустых папках, панель сжимается до `min-height`.

## Исправление

`DocLib.scss`: в `.citeck-doclib__pagination` стрелки `.ecos-pagination__arrow_new.ecos-btn`
ограничены `28px × 28px` (иконка 22px помещается; выше крошек 28px и ниже `min-height` панели).
Теперь всё содержимое панели ≤ 34px, и её высота всегда ровно 34 — с пагинацией, без неё и во
время загрузки. Специфичность `(0,3,0)` бьёт `button.ecos-btn` `(0,1,1)` независимо от порядка
загрузки стилей.

Не трогал `Pagination.scss` — тот же компонент стоит в тулбаре журналов, где 40px кнопка на месте;
и не стал держать `Pagination` смонтированной при `total = 0` — при равных высотах это не нужно.

Тест: `DocLib/__tests__/contextBarHeight.test.js` — компилирует `Btn.scss`, `Pagination.scss`,
`DocLib.scss` через sass CLI и по честному каскаду проверяет, что стрелка вне доклиба 40px
(предпосылка), а внутри `.citeck-doclib__pagination` — не выше `min-height` панели, при обоих
порядках загрузки. Без фикса тест падает (`40 > 34`). Хелперы каскада вынесены из
`styles/__tests__/bootstrapTooltipRoot.test.js` в `src/testUtils/cssCascade.js` (компиляция через
stdin с подстановкой алиаса `@/`, который sass CLI не знает).

Проверено в браузере после фикса: панель 34px и граница на 212px в корне, в папке с содержимым, в
пустой папке и на всём протяжении загрузки (ответ бэкенда искусственно задержан на 1.5 с).
