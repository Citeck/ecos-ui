# Lexical: кнопки «добавить строку/колонку» уезжают за границы формы (COREDEV-326)

## Проблема

После того как колонкам разрешили менять ширину (COREDEV-326, коммит `efc2dd423`), тестировщик
вернул задачу: если таблица перестаёт помещаться по ширине формы, кнопки таблицы, появляющиеся при
наведении курсора, ведут себя неправильно.

1. Кнопка **«добавить колонку»** (справа от таблицы) отображается за пределами видимой области формы.
2. Кнопка **«добавить строку»** (снизу) выходит за правую границу формы и **перекрывает
   горизонтальную полосу прокрутки**.
3. Зона наведения для обеих кнопок слишком узкая, кнопки появляются с заметной задержкой — «сложно попасть».

### Воспроизведение

1. Вставить таблицу в редактор (комментарий, описание задачи, вики-страница — любой `ecos-rt-editor`).
2. Растянуть колонку так, чтобы суммарная ширина таблицы превысила ширину контейнера — появляется
   горизонтальная прокрутка.
3. Навести курсор на ячейку последней строки → кнопка «добавить строку»; на ячейку последней колонки
   → кнопка «добавить колонку».

Замеры на локальном стенде (таблица 1245 px в контейнере 873 px, редактор 272…1226 px):

| | до исправления | после |
|---|---|---|
| «добавить строку», правый край | 1545 px (за пределами формы) | 1173 px (правый край контейнера) |
| «добавить строку», верх | 760 px — поверх полосы прокрутки (755…765) | 770 px — под полосой прокрутки |
| «добавить колонку» при частичной прокрутке | 1238 px (за пределами контейнера) | 1178 px |

## Корневая причина

### 1. В приложении и в playground — **разные темы**

`src/components/editors/Lexical/plugins/TableHoverActionsPlugin` — общий плагин, но тема у боевого
редактора своя: `LexicalEditor/themes/DefaultTheme` с префиксами `LEd__` / `rt-editor-theme__`.
Класс `PlaygroundEditorTheme__*` в работающем приложении **не встречается никогда**.

Плагин проверял прокручиваемый контейнер по жёстко заданному классу playground-темы:

```ts
if (parentElement.classList.contains('PlaygroundEditorTheme__tableScrollableWrapper')) {
  tableHasScroll = parentElement.scrollWidth > parentElement.clientWidth;
}
```

Реальный класс — `LEd__tableScrollableWrapper`, поэтому `tableHasScroll` всегда `false`, и кнопка
строки позиционировалась по **полной** ширине `<table>` (1245 px), а не по видимой части.

### 2. Кнопка колонки не учитывала обрезку в принципе

`left: tableElemRight + 5` — правый край самого `<table>`. Таблица шире контейнера обрезается им,
её `getBoundingClientRect().right` лежит за пределами видимой области, и кнопка уезжала следом.

### 3. Кнопка строки становилась поверх полосы прокрутки

`top: tableElemBottom + 5`. У контейнера с `overflow-x: auto` полоса прокрутки занимает область между
`clientHeight` и `offsetHeight`, то есть ровно ниже нижней границы таблицы.

### 4. Зона наведения

Кнопки показывались только пока курсор находится на ячейке (`getMouseInfo` → `closest('td/th')`) или
на самой кнопке. Зазор в 5 px между таблицей и кнопкой — а при прокрутке ещё и полоса прокрутки —
не принадлежит ни ячейке, ни кнопке: по дороге к кнопке она успевала исчезнуть. Плюс debounce
`50 / maxWait 250` мс добавлял задержку появления.

## Исправление

Новый модуль `plugins/TableHoverActionsPlugin/utils.ts`:

- `getTableScrollWrapper(tableElem, theme)` — контейнер ищется по классу **текущей** темы
  (`theme.tableScrollableWrapper`); если тема класс не задаёт, Lexical задаёт `overflow-x: auto`
  прямо в атрибуте `style` — этот вариант тоже поддержан;
- `getVisibleTableBox(tableElem, wrapper)` — видимая часть таблицы в координатах видимой области окна:
  пересечение прямоугольника таблицы с client-боксом контейнера. Отдельно возвращается `outerBottom`
  (нижняя граница border-бокса контейнера, то есть **под** полосой прокрутки);
- `getAddRowButtonPosition` / `getAddColumnButtonPosition` — позиции кнопок от видимых границ;
- `isPointerNearTable(x, y, tableElem, theme)` — курсор считается «у таблицы» в пределах
  `HOVER_MARGIN_PX = 25` (ширина кнопки + зазор) вокруг видимого бокса. Пока он там, кнопки не
  скрываются, даже если под курсором ни ячейка, ни кнопка.

В плагине: последняя таблица под курсором хранится в `hoveredTableDOMNodeRef`; ветка `isOutside`
скрывает кнопки только когда курсор ушёл и из зоны наведения. Debounce — `16 / maxWait 50` мс.

Когда таблица помещается в контейнер, все формулы дают прежний результат — поведение не меняется.

## Проверка

- `src/components/editors/Lexical/plugins/TableHoverActionsPlugin/__tests__/utils.test.ts` —
  11 тестов на геометрию (числа взяты из живого воспроизведения).
- Полный прогон `jest`: 221 набор тестов / 2842 теста — зелёные.
- Браузерная проверка на локальном дев-сервере, редактор описания задачи и вики-редактор (модальное
  окно): кнопки в границах контейнера, полоса прокрутки не перекрыта, клик по кнопке через полосу
  прокрутки и через зазор добавляет строку/колонку.
- Задержка появления кнопки (медиана по 5–6 прогонам): быстрое проведение курсора 50 → 27 мс,
  подвод в 4 шага 103 → 51 мс.

## Смежная находка (вне задачи)

`plugins/CodeActionMenuPlugin/index.tsx:150` содержит такой же жёстко заданный класс playground-темы:
`target.closest('code.PlaygroundEditorTheme__code')`. В `DefaultTheme` класс блока кода —
`LEd__code`, то есть меню действий над блоком кода (копировать / prettier) в приложении не
появляется никогда. Не исправлялось в рамках COREDEV-326.
