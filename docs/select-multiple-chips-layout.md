# Множественные select'ы: действия и значения «уезжают» за границы чипа (COREDEV-14)

Задача содержала два независимых дефекта — по одному на каждый из двух компонентов, которые рисуют
выбранные значения синими «таблетками» (чипами). Общего кода у них нет: это разные реализации с
разными механизмами вёрстки, и сломаны они по-разному.

| | SelectJournal (`multiple`) | EcosSelect (`multiple`) |
|---|---|---|
| откуда чипы | React, `InputView.jsx` → `li.select-journal__values-list_text-content` | choices.js, `div.choices__item` |
| действия | pencil + ✕, `position: absolute`, видны по `:hover` | ✕, инлайн-кнопка `.choices__button` |
| дефект | на метках в 1–2 символа блок действий шире чипа и вылезает за его левую границу | метка длиннее поля переносится, ✕ падает на вторую строку |
| исправление | `min-width: 60px` (коммит `3f83f495b`, уже в `develop`) | одна строка + ellipsis, см. ниже |

## Дефект 1. SelectJournal — действия шире чипа

### Механизм

`src/components/common/form/SelectJournal/InputView/InputView.scss`: блок действий вынесен из потока
(`position: absolute; right: 14px; top: 4px`) и наложен поверх хвоста метки — с градиентной подложкой
`transparent → --primary-color 25%`, чтобы текст под иконками уходил в размытие. Из потока он
изъят, поэтому **на ширину чипа не влияет вообще**: чип шириной по метке, а блок действий —
фиксированные ~43 px (12 px padding + 14 px pencil + 3 px gap + 14 px ✕).

Пока метка длиннее ~43 px, всё сходится. На метке в 1–2 символа чип ужимается до ~41 px, а блок
действий, прибитый к правому краю, вылезает влево — поверх соседнего чипа. Отсюда и картинки в
задаче: наводишь на `UI` — иконки рисуются поверх `PlanningSupport`.

### Состояние

Уже исправлено в `develop` коммитом `3f83f495b`: чипу задан `min-width: 60px`, что даёт блоку
действий ровно 3 px запаса внутри чипа. Замеры на локальном стенде (форма `ecos-type`, поле
`components` типа `ept-issue`, значения `A` / `UI` / `ORD`):

| чип | ширина `li` | левый край блока действий относительно левого края `li` |
|---|---|---|
| `A` | 60 px | **+3 px внутрь** |
| `UI` | 60 px | +3 px внутрь |
| `ORD` | 61.3 px | +1.3 px внутрь |
| длинная метка | 345 px | +288 px внутрь |

С принудительно снятым `min-width` (инъекция стиля только в браузере) чип `A` ужимается до 41.4 px, а
блок действий уходит на **15.6 px за левую границу** — то самое поведение из задачи. То есть
`min-width` действительно держит вёрстку, а не маскирует что-то другое.

Побочный эффект, принятый как норма (он же на скриншоте в задаче помечен зелёной стрелкой как
корректный): на метке в 1–2 символа непрозрачная часть градиента накрывает чип целиком, и по ховеру
метка полностью скрывается за двумя иконками.

⚠️ 60 px — константа, завязанная на размеры иконок: 43 px блока действий + 14 px правого padding.
Запас 3 px. Меняются иконки или `padding` — пересчитывать.

### Компактный режим — не при чём

`SelectJournal.scss:20-54` (`.select-journal_compact`) переопределяет и `min-width` (31 px), и
`right` (2 %), из-за чего блок действий там ушёл бы за край на ~9 px. Но `InputView.renderList()`
при `isCompact` возвращает `null` — чипы в компактном режиме не рисуются вовсе, вместо них
`renderCompactList()` печатает значения через запятую. Эти правила мертвы.

## Дефект 2. EcosSelect — ✕ переносится на вторую строку

### Механизм

`ecosSelect` — это **не** react-select, а choices.js. Разметка чипа приходит из дефолтного шаблона
`item` библиотеки (обёрнут в `src/forms/choices/index.js` ради локализации кнопки), метка — из опции
`template` компонента:

```html
<div class="choices__item choices__item--selectable">
  <span>Затраченное время</span>
  <button class="choices__button">Удалить элемент</button>
</div>
```

Вендорный `src/components/forms/EcosForm/formio.full.min.css` задаёт этому чипу
`display: inline-block` + `word-break: break-all`, и **не задаёт** ни `white-space: nowrap`, ни
`max-width`, ни `text-overflow`. Проектный оверрайд (`components/override/select/select.scss`) красил
чип, но вёрстку не трогал.

Итог: ширина inline-block'а — `min(max-content, доступная)`. Как только метка вместе с кнопкой не
влезает в поле, чип растягивается на всю ширину поля, метка занимает первую строку, а инлайновая
кнопка ✕ переносится на вторую. Чип становится ровно вдвое выше (52 px вместо 26), а `border-radius:
100px` превращает его в бесформенное пятно.

Ровно так это и выглядело: на стенде поле шириной 183.8 px, метки `Затраченное время`,
`Продолжительность`, `Статус документа` — по 154 × **52** px, ✕ у всех трёх на второй строке, флашем
влево. Поле целиком — 279 px против 130 px у соседнего SelectOrgstruct.

### Исправление

Тот же приём, который у одиночного значения (`.choices__list--single`) уже был в
`custom/ecosSelect/style.scss`: чип — строка из двух элементов, метка сжимается с многоточием,
кнопка держит свою ширину. Правила добавлены в `components/override/select/select.scss`, туда же,
где лежит остальная стилизация чипа:

```scss
.choices__list--multiple .choices__item {
  display: inline-flex;
  align-items: center;
  max-width: 100%;
  white-space: nowrap;
  overflow: hidden;

  &:has(> span:empty) { display: none; }
  > span { @extend %ellipsis; }

  .choices__button { flex: none; min-width: 0; overflow: hidden; }
}
```

Три неочевидных места:

1. **`min-width: 0` на кнопке обязателен.** choices.js держит кнопку в 8 px и прячет её текст
   (`Удалить элемент`) через `text-indent: -9999px`. Пока кнопка — inline-block, `width: 8px`
   работает. Став flex-элементом, она получает `min-width: auto`, то есть минимальный размер по
   содержимому, и раздулась бы до ширины спрятанной надписи.
2. **`:has(> span:empty)` приходится повторять.** Правило, прячущее чип без метки, живёт в
   `src/forms/choices/style.scss` со специфичностью `(0,2,1)`; блок выше — `(0,4,0)` и перебил бы его
   `display`.
3. **`word-break: break-all` не сбрасывается** — он остаётся в вычисленных стилях, но при
   `white-space: nowrap` переносов не происходит вовсе, так что правило инертно.

### Результат

Замеры там же, форма `ecos-type` → вкладка Roles → поле «Атрибуты»:

| чип | было | стало |
|---|---|---|
| Затраченное время | 154 × **52** | 157.8 × **26** |
| Продолжительность | 154 × **52** | 157.8 × **26** |
| Статус документа | 154 × **52** | 157.6 × **26** |
| Дата начала / Пользователь / Creator | 26 | 26 |
| высота поля целиком | 279.3 px | **180.6 px** |

Кнопка ✕ у всех чипов — в 8 px от правого края чипа (его `padding-right`), размер 22 × 14 px, ровно
как до исправления. Многоточие действительно рисуется: у `Затраченное время` `scrollWidth` 120 против
`clientWidth` 108, у `Продолжительность` — 126 против 108.

## Как воспроизвести

Обе половины задачи сходятся на одной форме — `uiserv/form@ecos-type` (редактирование типа данных):

* вкладка Roles → строка роли → **«Участники роли»** (`selectOrgstruct`, multiple) рядом с
  **«Атрибуты»** (`ecosSelect`, multiple) — это в точности скриншот из задачи, с корректным
  orgstruct для сравнения;
* первая вкладка → **«Действия»** (`selectJournal`, multiple) — множественный SelectJournal.

Путь: `/v2/dashboard?recordRef=emodel/type@<id>` → дашлет Actions → `Edit Properties`
(именно `.ecos-actions-list__item-title`; одноимённая ссылка в виджете «Метаданные» уводит со
страницы). Форма открывается в модалке, при этом в DOM висят **две** её копии — селекторы надо
сужать до видимой.

Гритча стенда: гриды `modelAttributes` / `modelRoles` возвращаются пустыми для всех типов, хотя
`model.attributes` заполнен, — строки в них приходится добавлять руками. Список опций «Атрибутов» —
это `dataSrc: custom`, читающий `data['modelAttributes']`, так что без заполненного грида выбирать
там нечего.

Для дефекта 1 нужны метки в 1–2 символа: на стенде для этого заведены записи `emodel/ept-components`
с именами `A`, `UI`, `ORD` в воркспейсе `TEST2`.

## Что защищает от регрессии

Вёрстку в jsdom не проверить — там нет layout'а. Поэтому `EcosSelect.spec.js` пиннит **разметку, на
которую написан CSS**: чип на каждое значение, метка — прямой `<span>` ребёнок чипа (цель
многоточия), кнопка с классом `.choices__button` внутри чипа. Ни один из этих селекторов не
порождается этим репозиторием — они приходят из choices.js и из опции `template`, поэтому и могут
уехать молча. Плюс проверка, что сами правила из стилей никуда не делись.

Смотри также `src/forms/choices/__tests__/itemTemplate.spec.js` — там пиннится локализация той же
кнопки ✕.
