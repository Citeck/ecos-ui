# Редактор матриц прав и workspace (COREDEV-610)

Матрица принадлежит пространству своего типа. При сохранении редактор передаёт
полный `typeRef`, права и права атрибутов; явно задавать `workspace` или `_workspace`
не требуется. Backend определяет WS по типу и проверяет доступ в нём.

Общий `Records.save()` может автоматически добавить WS текущей страницы. Для
полного `typeRef` этот контекст не влияет на создание матрицы. Поэтому менеджер
может сохранить матрицу своего типа со страницы другого WS, а администратор —
глобальную матрицу со страницы WS. Контекст нужен для `CURRENT_WS` при импорте;
целевой WS деплоя ecos-app проверяется отдельно, включая SYSTEM.

Поиск существующей матрицы возвращает ссылку с префиксом WS и вычисляемый
атрибут `workspace` на основе её типа. Backend также предоставляет вычисляемый
`workspaceRef`. Это атрибуты чтения, а не поля общего DTO.
Удаление передаёт в Records API ссылку матрицы и возвращает promise запроса.

Экспорт из редактора оставляет локальный ID матрицы, убирает поле `workspace`
и заменяет префикс WS в `typeRef` на `CURRENT_WS:`. Явно построенные `id` и `typeRef`
имеют приоритет над содержимым загруженного объекта. Это позволяет импортировать
матрицу вместе с типом в другой WS. Глобальные ссылки сохраняются без изменений.
Источник ссылки, локальный ID и удаление префикса WS разбираются отдельными
именованными шагами. При удалении WS-префикса сохраняется namespace самого типа.

Backend запрещает `:` в новых локальных ID матриц; WS-префикс ссылки допустим.
Тип с namespace при создании матрицы без явного ID получает UUID матрицы.
Повторное сохранение сохраняет её ID. Старые матрицы с `:` остаются редактируемыми
и экспортируемыми, но для импорта в новый WS их ID нужно заменить на ID без `:`.

### Живая проверка без явного workspace-контекста — 07.10.2026

UI из текущих исходников запущен на `http://localhost:3000`, API проксируется
в настоящий локальный стек. В этой проверке HTTP не подменялся. Model и uiserv
обновлены локальными образами через HTTP API Launcher по Unix socket.
Общий `TypePermsDef` и версия model-lib 2.40.2 остаются исходными. В реальном
запросе создания матрицы проверены полный `typeRef`, отсутствие поля `workspace`
и обычный `_workspace` текущей страницы, добавленный общим `Records.save()`.
Редактор не назначает и не переопределяет этот контекст.

Дополнительно через зарегистрированное продуктовое действие в реальном браузере
открыты редакторы типов вне текущего журнала: менеджер A создал матрицу типа A
со страницы B, а администратор — глобальную матрицу со страницы A. В запросах
контекст страницы B/A сохранился, но матрицы сохранены в A/глобальной области
по полным ссылкам типов. Эти сценарии используют настоящий UI и API.

Пользователь `fet` без глобальных административных прав, менеджер временного
WS A, открыл форму своего типа, создал матрицу READ, переключил ячейку в WRITE
и сохранил. Реальное право записи документа изменилось соответственно.
Пункт «Матрицы прав» и журнал в локальной админке видны; удаление из журнала
работает и восстанавливает право записи. Обычному участнику `director` API
отказывает в изменении и удалении матрицы.

Скачанный настоящим UI JSON не содержит `workspace`, оставляет локальный ID
и `CURRENT_WS:` в ссылке типа. Импорт этого файла через настоящий ecos-app
в WS B завершился `DEPLOYED`; сохранение разных прав при одинаковом локальном
ID в A/B не затрагивает соседний WS. Отдельно проверены отказ деплоя матрицы
на глобальный и чужой тип (`DEPLOY_FAILED`) и успешный пакет собственного типа с матрицей.

Журнальный «Редактор JSON» получает переносимый `_self?json` без `workspace`.
Сохранение менеджером через штатный редактор и API `_self` сохраняет исходный
WS и ссылку типа. Поля `workspace` в общем DTO нет; backend-регрессия проверяет
исходные четыре поля JSON и обратное сохранение.

Сделаны и просмотрены реальные скриншоты. Все временные данные удалены;
конфигурации 35 прежних матриц полностью совпадают с исходным снимком.

### Структурированный ID матрицы — 08.10.2026

Backend использует `IdInWs` для чтения, метаданных, удаления и серверного снимка
матрицы. Строки остаются транспортным форматом Records; общий JSON DTO и код
редактора не меняются. На этом этапе локальный ID по умолчанию сохранял namespace
типа при повторном сохранении и JSON roundtrip в WS, включая namespace,
совпадающий с system ID другого пространства. Для новых матриц теперь действует
описанный выше запрет `:` и генерация UUID. Экспорт сохраняет namespace типа после
`CURRENT_WS:`. Удаление артефакта работает напрямую по `IdInWs`, без повторного
разбора локального ID как отдельного workspace-префикса.

Живой прогон этого контракта: редактор настоящего типа с namespace сохранил
READ/WRITE, экспорт сохранил `CURRENT_WS:namespace:...`, импорт в другой WS
завершился DEPLOYED. Настоящий JSON-редактор сохранил scope и namespace;
удаление матрицы восстановило запись документа. Скриншоты просмотрены.
Новые fixtures удалены; 35 исходных конфигураций полностью неизменны.
Результаты в Solution `.tmp/coredev-610/id-in-ws/verification.json`.
UI source в этой фазе не менялся, использован существующий production build.
