# Пагинация страницы журналов: глобальный конфиг (COREDEV-583)

## Что это

Глобальный ecos-config uiserv `journals-pagination` задаёт, сколько строк показывает **страница журнала**
(`/v2/journals`, и журнал в разделе администрирования — там тот же компонент `Journals`). Виджет журнала
на дашборде и конфиг журнала не затрагиваются.

```json
{ "journalsPage": { "pageSizeMode": "AUTO" | "FIXED", "pageSize": 25 } }
```

- `AUTO` (по умолчанию, и если конфига нет вовсе — старый uiserv) — как раньше: количество строк
  подбирается по высоте окна.
- `FIXED` — ровно `pageSize` строк (целое, 1…1000) независимо от высоты окна; лишнее прокручивается.
  `pageSize` читается только в этом режиме; в `AUTO` он игнорируется, даже если задан.

Секция `journalsPage` — задел: рядом можно добавить настройки для виджета, не меняя конфиг.

Редактирование: «Конфигурация ECOS» → «Пагинация журналов». Форма `uiserv/form@config-journals-pagination`:
панель «Страница журнала», селект режима и поле «Строк на странице» (видно только в `FIXED`).
Артефакты лежат в ecos-uiserv: `app/config/journals-pagination.yml`,
`ui/form/config/config-journals-pagination.json`.

## Как устроено в UI

- `ConfigService`: ключ `JOURNALS_PAGINATION` (`TYPE_JSON`, default `{}`), грузится батчем вместе с
  остальными конфигами (`$cfg.journals-pagination?json` на `uiserv/meta@`).
- `sagas/app.js` → `initApp` кладёт значение в `view.journalsPagination` **до** рендера журналов —
  так же, как `new-journal-enabled`. Поэтому первый запрос данных страницы уже идёт с нужным `maxItems`
  (асинхронная подгрузка конфига в самом компоненте дала бы гонку с первым запросом).
- `selectJournalsPageFixedPageSize` (`selectors/view.js`) — число при `pageSizeMode: 'FIXED'` (константы `PageSizeMode` рядом с `DEFAULT_PAGINATION`) и корректном
  `pageSize`, иначе `null`.
- `JournalsDashletPagination.componentDidUpdate` — единственное место, где страница считала размер по
  высоте; при фиксированном количестве вместо расчёта берётся оно (для таблицы и превью-списка; плитки,
  как и раньше, не пересчитываются). Дашлет сюда не заходит: ему не передают `isViewNewJournal` и
  `maxHeightJournalData`.
- Выпадашки размера страницы в новом виде журнала нет, поэтому фиксированное число просто становится
  `grid.pagination.maxItems`.

## Гоча: белая полоса под таблицей

`.ecos-journal-dashlet__grid-wrapper::after` — белая полоса 15px (z-index 20) поверх низа области
прокрутки грида. В новом виде журнала у таблицы `margin-bottom: 0 !important`, и расчёт по высоте
всегда оставляет под последней строкой ≥15px, так что раньше строки под полосу не попадали. Фиксированное
количество может не влезть в окно — тогда последняя строка при полной прокрутке оставалась наполовину под
полосой. Решение: модификатор `ecos-journal_fixed-page-size` на корне `Journals` (только в фиксированном режиме)
даёт обёртке таблицы (`ecos-grid__table-wrapper` — свой класс, передан в `BootstrapTable` через
`wrapperClasses`) `padding-bottom: 15px`. Не `margin` самой таблицы: он обнулён через `!important`, и
перебить его можно было бы только ещё одним `!important`. В автоматическом режиме ничего не меняется.

## Проверка

- jest: `src/selectors/__tests__/view.test.js`, `JournalsDashletPagination/__tests__` (авто 23 строки,
  FIXED 15, FIXED меньше авто-минимума, превью-список, дашлет не трогается — без фикса 3 теста красные),
  `src/sagas/__tests__/app.test.js` (конфиг кладётся в стор).
- Браузер (журнал `ecos-journals`, ответ `uiserv/meta@` с конфигом подменён): без конфига — 23 строки
  при окне 900, 12 при 600 (как раньше); `FIXED/15` — один запрос `maxItems: 15`; `FIXED/40` при окне
  600 — 40 строк, прокрутка, последняя строка видна и кликабельна; виджет журнала на дашборде — 10.
- Форма (EcosForm на реальном JSON-конфиге стенда, `mutate` перехвачен): вложенные контейнеры
  `_value → journalsPage` загружаются, пустое и 0 не сохраняются, уходит
  `_value: { journalsPage: { pageSizeMode: 'FIXED', pageSize: 25 } }`.
