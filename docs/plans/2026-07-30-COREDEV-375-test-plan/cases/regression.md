# Cases: Регрессия (R1–R4)

Области, задетые правками, но **не относящиеся** к четырём исходным дефектам. Возникли в последнем
раунде: при оценке вывода Codex ревьюер прогнал линтер по всему модулю ассистента и починил две
предсуществующие ошибки в файлах, которых ветка до того не касалась.

## R1. Редактор скриптов рендерится после подъёма DIFF_STYLES
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: открыть запись с полем-скриптом → вызвать помощника по скриптам → получить предложение
  правки → открыть просмотр различий.
- **Acceptance**: `ScriptDiffViewer` рисуется, различия видны, кнопка применения работает.
- **Note**: правка убрала `useMemo`, стоявший **после раннего `return null`** — нарушение порядка
  хуков, из-за которого React мог получать разное число хуков между рендерами. Codex подтвердил, что
  это был реальный риск, а не косметика линтера. Объект статический, поднят на уровень модуля.

## R2. Выпадающий список агентов отображается корректно
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: открыть список агентов, осмотреть все записи.
- **Acceptance**: значки и подписи движков на месте; **кавычки в текстах отображаются как кавычки,
  а не как `&quot;`**.
- **Note**: правка заменила литеральные кавычки на HTML-мнемонику ради `react/no-unescaped-entities`.
  Ревьюер утверждал, что результат рендера не меняется — этот кейс проверяет утверждение глазами.
  Риск конкретный: мнемоника, попавшая в текстовый узел не там, где ожидалось, отобразится буквально.

## R3. Обычное сообщение с действиями не сломано
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: получить обычный markdown-ответ с кнопками (ветка `MessageItem`, не карточка) —
  например, подтверждение изменения записи.
- **Acceptance**: кнопки рисуются, порядок прежний (отменяющая слева, подтверждающая справа),
  подписи локализованы, клик работает.
- **Note**: `MessageActions` переписывался в каждом из шести проходов ревью; порядок кнопок и
  локализация подписей — существующее поведение, которое легко задеть.

## R4. Очистка контекста создаёт новый диалог
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: провести диалог с гейтом → нажать очистку контекста → задать новый вопрос.
- **Acceptance**: история пуста, новый `conversationId`, кнопки прошлого диалога не всплывают.
- **Note**: ревью отметило предсуществующее ограничение в `clearConversation`/опросе, но
  сознательно не трогало — проверяем, что оно не усугубилось.
