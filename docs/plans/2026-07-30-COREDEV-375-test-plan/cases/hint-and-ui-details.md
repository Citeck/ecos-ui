# Cases: FE-2 подсказка гейта (H1–H4), FE-3 placeholder (P1–P3), FE-4 изменение размера (Z1–Z2)

## H. Подсказка гейта плана — FE-2

Реализация: `AgentPlanMessage.jsx` — `isGateLive = !actionsDisabled && !messageData.actionsResolved`,
подсказка рисуется при `hint && isGateLive && !messageData.actions?.length`.

> ⚠ **Это самый непокрытый раздел.** Ни один прогон ревьюера не сумел получить карточку
> `WAITING_PLAN_APPROVAL` на стенде, поэтому FE-2 держится исключительно на модульных тестах.
> Первоочередная задача — воспроизвести карточку. Если ни один агент её не выдаёт, зафиксировать
> это как пробел покрытия с указанием, что именно пробовали.

## H1. Отклонение плана убирает подсказку вместе с гейтом (A3)
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: довести диалог до карточки плана с кнопками подтверждения и отклонения → отклонить →
  дождаться терминального сообщения.
- **Acceptance**: кнопки плана неактивны; подсказка «Подтвердите план, предложите изменения или
  задайте вопросы» **отсутствует** в DOM; степпер очищен.
- **Note**: исходный дефект был инверсным — обнуление `actions` при клике открывало подсказке
  дорогу, и она появлялась именно в терминированном диалоге.

## H2. Подтверждение плана — то же самое (A4)
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: повторить H1, но подтвердить план.
- **Acceptance**: подсказки нет, кнопки неактивны, выполнение началось.

## H3. Живой гейт без кнопок подсказку показывает
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: получить карточку `WAITING_PLAN_APPROVAL`, у которой бэкенд не прислал `actions`.
- **Acceptance**: подсказка **видна** — полезное поведение не должно было пострадать.
- **Note**: если такую карточку не получить, отметить SKIP; модульные тесты 18–21 покрывают.

## H4. Терминальная карточка ошибки подсказки не показывает
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: довести до карточки со статусом `FAILED` (например, оборвать выполнение шага).
- **Acceptance**: подсказка `hint-failed` не появляется у устаревшей карточки.
- **Note**: ревью отметило, что `hint-failed` рисуется только при отсутствии кнопок — тот же класс,
  что FE-2, предсуществует на `develop`.

## P. Placeholder поля ввода — FE-3

Реализация: `ChatInput.jsx` → `resolvePlaceholderKey`, ключ выбирается по
`getAgentEngine(selectedAgent)`.

## P1. Placeholder меняется по движку агента (A8)
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: открыть ассистента без выбранного агента → снять placeholder → выбрать «Помощник по
  задачам и документам» (`TOOL_LOOP`) → снять → выбрать «Агент конфигурации платформы» (`CONFIG`) →
  снять.
- **Acceptance**: без агента — «Опишите, что вы хотите создать...»; `TOOL_LOOP` — «Спросите о
  задачах, документах или записях...»; `CONFIG` — снова «Опишите, что вы хотите создать...».

## P2. Контекстная вкладка сохраняет свой placeholder
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: переключиться на контекстную вкладку при любом выбранном агенте.
- **Acceptance**: «Введите ваш запрос...» вне зависимости от агента.

## P3. Наблюдение: несогласованность при невыбранном агенте
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: без выбранного агента открыть выпадающий список агентов и сравнить значок движка у
  записи по умолчанию с формулировкой placeholder.
- **Acceptance**: зафиксировать факт (не дефект правки): placeholder показывает конфигурационную
  формулировку, а значок помечает ту же запись как операционную. Решение плана (случай 22) —
  оставить как есть; ревью подтвердило четырежды. Вторая такая же ветка — редактирование скрипта
  перенаправляется на конфигурационного агента, а placeholder остаётся операционным.

## Z. Изменение размера окна — FE-4

Реализация: `AIAssistantChat.jsx` — `resizeHandles` из двух констант модуля вместо
несуществующего пропа `disableResize`.

## Z1. Нет предупреждения React про disableResize (A9)
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: открыть чат → свернуть → развернуть → снять `browser_console_messages` за всю сессию.
- **Acceptance**: ни одного сообщения, содержащего `disableResize`. Дополнительно через
  `browser_evaluate` убедиться, что на внутреннем `div` компонента остались только атрибуты
  `class` и `style`.
- **Note**: предупреждение об неизвестном пропе React выдаёт только в отладочной сборке — dev-сервер
  для этого кейса подходит лучше промышленной сборки.

## Z2. Изменение размера работает развёрнутым и недоступно свёрнутым
**Tier:** B • **Cluster:** 1 • **Tools:** `[PW]`
- **Шаги**: в развёрнутом окне потянуть за маркер изменения размера → свернуть → проверить наличие
  маркера в DOM.
- **Acceptance**: развёрнутым размер меняется; свёрнутым маркер `.react-resizable-handle`
  отсутствует (пустой список `resizeHandles` его не рендерит).
