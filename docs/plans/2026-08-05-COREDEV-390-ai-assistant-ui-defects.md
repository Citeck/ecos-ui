## Сделано

### D-B-1 — всплывающие панели поля закрывали правимый текст

Обе панели (быстрых действий и результата) рендерились через Popper с якорем на кнопке ассистента,
расположением `bottom-end` и ограничением только по границам окна. Панель шириной 485–600 px уезжала
за левый край поля и закрывала боковое меню и начало каждой строки.

- `AIPopperWrapper.tsx` — новое свойство `boundaryElement`; модификатор `fieldBoundary` (фаза `main`,
  после `preventOverflow`) сдвигает панель внутрь горизонтальных границ поля; ширина во всех
  вариантах ограничивается шириной поля. Чистая функция `clampToFieldBounds` вынесена для тестов.
- `AIFieldActions.tsx` — свойство `fieldElement`, прокинуто в обе панели.
- Точки подключения: `AIAssistantButton.tsx` (корень редактора через `registerRootListener`),
  `AIFloatingPopup.tsx`, `TextArea.jsx` → `TextAreaAIButton.jsx`.

Прежняя зацепка из отчёта (класс `ai-actions-bar--code-editor`) к дефекту отношения не имела.

### D-B-2 — быстрые действия simplify и formalize не выведены в интерфейс

Список действий захардкожен во фронте (эндпоинта со списком нет — утверждение отчёта было неверным).

- `fieldActionConfigs.ts` — действия добавлены для `TEXTAREA`, `RICHTEXT`, `DOCUMENTATION`;
  идентификаторы строго `simplify` / `formalize` (ключи, по которым бэкенд ищет промт).
- `ru.json` / `en.json` — «Упростить» / «Деловой стиль», Simplify / Formal style.

### D-B-7 — карточка вечно висела на «Обработка 5 %»

Три отдельные поломки, каждая исправлена:

1. `usePolling.js` — ответ неизвестной формы не попадал ни в одну ветку: опрос молча умирал, ввод
   оставался заблокированным навсегда. Добавлена ветка с ошибкой.
2. `useUniversalChat.js` (`handlePollingError`) — переписывался только текст, `messageData` со
   стадией и процентом оставался, а устаревший `detailedStatus` полностью скрывал ошибку. Теперь
   сбой проставляется в `messageData`, сбрасываются `activeBusinessAppProgress` и `agentStatus`.
3. `fetchStatus` — 404 распознаётся отдельно и объясняется человеческим текстом
   (`ai-assistant.chat.request-lost`); признак `requestLost` передаётся вторым аргументом `onError`.

Плюс `MessageItem.jsx` — причина сбоя выводится под карточкой шагов агента (она рисуется только из
`messageData` и раньше молчала); стиль `ai-assistant-chat__progress-error` в `_progress.scss`.

### D-B-8 (половина) — английское «Remove item» в русском интерфейсе

`Select.js` и `EcosSelect.js` — переопределён шаблон `item` библиотеки choices.js 8.0.0 (константа
там жёстко зашита), подпись и `aria-label` берутся из `select.remove-item`.
Вторая половина («Inherit from parent or data source») живёт в `ecos-model`, артефакт
`ui/form/ecos-type.json:652` — по решению владельца в этой ветке не трогалась.

### D-B-10 — нечитаемый начальный масштаб диаграммы Mermaid

`MermaidDiagram.jsx`:
- встроенный SVG рисуется в натуральном размере (конфликт `width: 100%` + `min-width: 700px` убран),
  контейнер получил горизонтальную прокрутку (`_mermaid.scss`);
- полноэкранный режим открывается в масштабе «вписать в окно» (`measureFitZoom` меряет фактическую
  раскладку, деля текущий масштаб), кнопка «вписать» возвращает к тому же значению.

### D-B-12 — интерфейс терял причину отказа (найден в этой сессии)

`sendMessage` не читал тело ответа на `!ok`. Теперь показывается формулировка бэкенда (заметнее
всего на 409 «диалог занят предыдущим запросом»), а ошибки транспорта по-прежнему выводятся общим
текстом.
